## Inventory: carton QR stickers - scan a box to start using it (owner ask)

- Flow: a delivery arrives -> on /inventory register "N boxes x qty per
  box" for an item -> an A4 sticker sheet opens (8 per page: item + brand,
  qty, brief instruction, QR, carton id) -> stickers glued on boxes.
  Sealed boxes are NOT stock. When the floor opens a box they scan the QR
  (phone, logged in), land on /inventory/cartons/[id], tap "Start using
  this box" - the quantity is added to stock with ledger reason
  `carton_opened`.
- Idempotent: rescanning an opened box shows "Already opened" (who/when)
  and never double-adds. Unknown carton = loud 400.
- Data: `cartons[]` in inventory_store (sealed/opened, opened_by/at).
  "Sealed boxes (not yet in stock)" panel on /inventory shows per-item
  totals + Reprint stickers (?item= reprints all sealed of an item).
- Print sheet follows the A4 recipe (12mm, pt fonts, Helvetica, no
  transforms); QRs served by /api/qr (already on every role allowlist);
  QR payload uses NEXT_PUBLIC_APP_URL (erp.hagan.pro fallback).
- API parity: POST /api/inventory/cartons, POST
  /api/inventory/cartons/[id]/open (session) and POST
  /api/v1/inventory/cartons/open { carton_id } (API key); cartons listed
  in both GET routes. Events: `inventory.cartons_created`,
  `inventory.carton_opened`. Tests: `npm run test:inventory` (8 pass,
  incl. open-once + rescan guard). Smoke-tested end to end locally
  (register -> stickers -> scan -> rescan blocked), test data cleaned.

## Client name change requests (QC proposes, admin approves)

- Non-admins (QC etc.) can now propose a rename on the Clients page
  ("Request name edit" when names are locked). Pending proposal is stamped
  on the client (name_change_* fields), shown as an amber banner, and the
  requester can cancel it. Bulk PUT /api/clients always carries the stored
  request fields over so other saves can't drop a pending request.
- Admin sees a dashboard panel (+ stat card) with OK / Not buttons.
  Endpoints: POST /api/clients/[id]/name-change-request
  (request_change/cancel_request/approve/reject, role-gated) and
  /api/v1/clients/name-change-requests (API key parity, GET pending list).
  Events: client.name_change_requested/approved/rejected (+client.updated
  on approve). Zapier outbound list updated.
- One-click email actions: each admin's alert email now carries personal
  APPROVE and REJECT links that work without logging in (phone inbox).
  Links are HMAC-signed tokens (name-change-email-token.ts, secret =
  Supabase service role key / CRON_SECRET fallback) bound to client id +
  action + requested_at + recipient, 7-day expiry. GET
  /api/clients/name-change-email-action verifies and applies, returns a
  small HTML result page; route is session-exempt in middleware (token is
  the authorization). A newer proposal or an already-handled request
  invalidates old links ("Request was updated" / "Already handled").
  Actor is recorded as "<admin email> (email link)".
- Tests: npm run test:name-change (14 pass: request/approve/reject logic
  + token round-trip, tamper, expiry, wrong-secret). Verified live in dev:
  QC requested a rename, reject link cleared it without a session cookie,
  replay showed "Already handled", tampered token rejected.

  + Add point - "not working". Root cause: on set garments
  (Overshirt+Trouser etc.) the screen piece view only showed rows in the
  piece's dictionary allow-list. A custom point isn't in any dictionary,
  so the row was added and even saved, but NO piece view displayed it -
  the add looked broken. (Print already had an orphan rule appending
  custom rows to the first piece A4; the screen never got it.)
- Fix: shared trialSheetOrphanRows() in measurement-template-mode.ts is
  now used by BOTH the screen piece view

  it) so the two can never diverge again. Dictionary points tagged to
  other garments are still never shown.
- UX: after Add point on a set garment, the sheet auto-jumps to the piece
  view where the new row lives so it is visible immediately.
- Regression test added (custom point on first piece view, other-garment

  library suites pass (25 + copy tests).
