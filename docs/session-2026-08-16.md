## "Never again" hardening (same day, owner ask)

- Library-wide sweep found the same disease elsewhere; all vectors are now
  guarded, not just copy/paste:
  - `mergeTemplateMeasurements` (Load template points / Load entire /
    Load reduced) skips template rows whose normalized label already
    exists on the sheet under a different id - a shifted-id sheet can
    never regain a second hem row from a template load.
  - `buildMeasurementsFromTemplate` (sheet creation) dedupes dictionary
    points by normalized label (legacy dictionary has two "1/2 Hip" ids).
  - Shared `normalizeMeasurementRowLabel` in measurement-template-mode.ts
    ("1/2 hem width" == "1/2 hem"); copy/paste, template merge, and
    creation all use it. Executable test in `test:copy-measurements`
    (25 pass; measurement-template-mode.test.ts still cannot run
    standalone - pre-existing next/server import chain via mutations).
- Data sweep (`scripts/cleanup-measurement-clutter.ts`, full-store backup
  `tmp-pdf-inspect/backup-pattern-library-before-clutter-sweep.json`):
  - 8 all-empty 57-row Trouser sheets (Abdeliah x3, Al Moussa, Mohamad Al
    Ajlan x3, Elie Rahme) rebuilt to the 17 reduced points; Ibrahim Al
    Shwemi OT rebuilt (37 -> 37, already reduced-shaped). Only versions
    with zero entered values were rebuilt.
  - 7 mislabeled rows relabeled to their dictionary names (values kept),
