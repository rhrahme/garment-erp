## Print A4 leaked other-garment rows (FR-0626-0037, fixed)

- User (photos of the measurement chart vs the printed page): the print
  page showed EXTRA points and "mixed overshirt and short sleeve shirt
  measurements together" while the screen piece view was clean.
- Root cause: stitcher piece A4s append "orphan" rows (rows no piece
  owns) to the first piece page so custom points are never lost. Khaled's
  OT sheets carried 7 FILLED Shirt SS rows (Collar Height, Side Length,
  Sleeve Opening W/H, Chest Pocket W/H, Shoulder Slope) that the screen
  hides for the Overshirt piece - but the orphan rule printed them.
- Code fix (`expand-cutter-print-pages.ts`): dictionary points tagged to
  other garments are never orphans; only untagged/custom points still
  append to the first piece A4. Regression test added
  (`expand-cutter-print-pages.test.ts`, 6 pass).
- Data move: the 7 valued Shirt SS rows moved off Khaled's 6
  Overshirt/OT sheets onto his dedicated Shirt SS sheet
  (cp-1785530548436-5805); an empty "Shoulder" row was dropped.
- Verified against live data (`scripts/verify-print-pages-8690.ts`,
  mirrors PatternSheetPrintView): all 7 Khaled overshirt sheets print
  only overshirt/trouser rows on every article/piece page ("Collar
  Height (CB)" is a real overshirt dictionary point and stays).
